## Setup

1. Make sure you're on the right branch and the working copy is up to date:
   ```
   git checkout fix/1.0.2-bug-batch
   git pull
   ```
2. Copy the UAT fixture to a scratch location — **don't run the checklist
   against the copy in this folder directly**, since `Ctrl+S` during testing
   writes to disk and would dirty the fixture:
   ```
   cp uat-testing/uat-sample.journal /tmp/uat-sample.journal
   ```
   (or, on Windows PowerShell: `Copy-Item uat-testing\uat-sample.journal $env:TEMP\uat-sample.journal`)
3. Launch the editor against the scratch copy:
   ```
   python -m ledgerkit_editor /tmp/uat-sample.journal
   ```
   (or `ledgerkit-editor /tmp/uat-sample.journal` if installed as a console script)
4. The fixture contains: a `P` price directive and an "Opening balances"
   transaction both dated `2026-9-1` (unpadded), a `Groceries` transaction on
   `2024-01-15`, 20 filler transactions through February 2024 (to force
   scrolling), and a second `Groceries` transaction on `2024-03-01`.

## 1 — Shift+Up/Down on a `P` price-directive date

- [ ] Move the cursor onto the `P 2026-9-1 EUR 1.08 USD` line (line 4), anywhere
      within the date.
- [ ] Position the cursor on the month digit (`9`) and press **Shift+Up**.
  - **Expected:** the line becomes `P 2026-10-01 EUR 1.08 USD` — the date is
    both zero-padded *and* incremented in one keypress. The commodity/rate
    (`EUR 1.08 USD`) is untouched.
- [ ] Press **Shift+Down** once.
  - **Expected:** the line returns to `P 2026-09-01 EUR 1.08 USD`.
- [ ] Move the cursor onto the day digit and press **Shift+Up** a few times.
  - **Expected:** only the day increments; month/year/commodity unaffected.

*Prior to this fix, Shift+Up/Down did nothing on a `P` line — the cursor's
Up/Down text selection would move instead.*

## 2 — Unpadded dates (no leading zero) on a transaction header

- [ ] Move the cursor onto the `2026-9-1 Opening balances` header line (line 6).
- [ ] Position the cursor on the month digit (`9`) and press **Shift+Up**.
  - **Expected:** the header becomes `2026-10-01 Opening balances` in one
    keypress — expanded to zero-padded form *and* shifted.
- [ ] Undo (**Ctrl+Z**) back to `2026-9-1 Opening balances`.
- [ ] Confirm the date is syntax-highlighted as a date (same color as the
      other transaction dates in the file) — before this fix, an unpadded
      date wasn't recognised as a header at all and would show no date
      highlighting.
- [ ] Position the cursor on the day digit and press **Shift+Down**.
  - **Expected:** `2026-08-31 Opening balances` (day 1 underflows into the
    previous month, August, which has 31 days).

## 3 — Ctrl+C while the search bar has focus

- [ ] Press **Ctrl+F** to open the search bar.
- [ ] Type `Groceries` (matches the two Groceries transactions in the file).
      Confirm the counter shows `1 of 2` and the match is highlighted in the
      editor.
- [ ] With the search box still focused and nothing selected inside it,
      press **Ctrl+C**.
  - **Expected:** the matched text (`Groceries`) is copied to the clipboard.
    Paste it somewhere (e.g. into the search box itself, or an external
    editor) to confirm.
  - **Must NOT happen:** a "Press Ctrl+Q to quit" notification popping up, or
    the app closing.
- [ ] Now select some of the *typed query text* inside the search box itself
      (e.g. double-click a word, or Shift+Left/Right), then press **Ctrl+C**.
  - **Expected:** the selected query text is copied — this path must keep
    working unchanged.
- [ ] Clear the search box and type a single character (below the 2-character
      minimum), then press **Ctrl+C**.
  - **Expected:** nothing happens — no crash, no quit notification.

## 4 — Shift+PgUp scroll padding

- [ ] Close the search bar (**Escape**) if open. Make sure your terminal
      window is small enough that the 20 filler transactions don't all fit on
      screen at once (resize smaller if needed).
- [ ] Press **Ctrl+End** to jump to the end of the file, then **Shift+PgUp**
      repeatedly to step backward through the filler transaction headers.
  - **Expected:** as you approach the top of the visible viewport, at least
    ~4 lines of context remain visible *above* the cursor's line at all
    times — the cursor should never end up on the very first visible row of
    the editor pane.
  - **Compare against:** **Ctrl+Home** then **Shift+PgDown** repeatedly,
    moving forward — the same amount of context (~4 lines) should be kept
    *below* the cursor. The two directions should feel symmetric.
- [ ] Repeat the same comparison using search instead of transaction
      navigation: **Ctrl+F**, search `Filler`, then step backward with
      **Shift+PgUp** and forward with **Shift+PgDown** through the matches,
      confirming the same top/bottom context margin in both directions.

*Prior to this fix, only downward navigation kept a margin — moving upward
would scroll the cursor flush against the top edge of the editor pane.*

## Regression sanity (quick pass — not exhaustive)

These aren't new behavior, just a spot-check that the fixes above didn't
disturb anything adjacent:

- [ ] A normal, already-padded header date (e.g. `2024-01-15`) still shifts
      correctly with Shift+Up/Down.
- [ ] Shift+Up/Down on a posting line (not a header or `P` directive) falls
      through to normal text selection, as before.
- [ ] Shift+Up/Down on a non-`P` directive line (there isn't one in this
      fixture — you can add a line like `D 1.00 EUR` to test) falls through
      to normal text selection.
- [ ] `Ctrl+S` still saves the file without errors.
- [ ] `Ctrl+R` cleared/pending toggle still works on a header line.
