# UAT Checklist — 1.1.0 Filter (Ctrl+O) & Tab Autocomplete

**Branch:** `release/1.1.0`
**Covers:** Phases 3–4 of `planning/next-release-phase-plan.md` — the
Transaction Filter (`Ctrl+O`, smart dates + Python regex) and Tab
autocomplete (account/payee name completion) features. Phase 2 (the
`transaction_table.py` module split) is internal-only and has no UI to
click through — its correctness is covered entirely by the automated
suite. Phases 5–6 (the two Claude Code skills + `AI-README.md`) are
developer tooling, not app behavior — nothing to UAT there either.
**Automated coverage:** `test_query_match.py`, `test_date_parser.py`
(relative offsets), `test_filter_popup.py`, `test_journal_index.py`,
`test_autocomplete.py` — 431/431 passing as of this branch. As with the
1.0.2 checklist, this is the manual, real-terminal pass for things
automated tests can't fully stand in for (does the suggestion bar actually
look right, does the filter feel responsive, etc.).
**Prerequisite:** if you haven't already, see
[`SETUP.md`](SETUP.md) in this folder for how to get a venv onto
`release/1.1.0` for this pass.

---

## Setup

1. Follow [`SETUP.md`](SETUP.md) to install `release/1.1.0` into a venv,
   or confirm you're already on it: `git branch --show-current` should
   print `release/1.1.0`.
2. Copy the (updated) fixture to a scratch location — `Ctrl+S` during
   testing writes to disk, and you don't want to dirty the copy in this
   folder:
   ```
   cp uat-testing/uat-sample.journal /tmp/uat-sample.journal
   ```
   PowerShell: `Copy-Item uat-testing\uat-sample.journal $env:TEMP\uat-sample.journal`
3. Launch: `python -m ledgerkit_editor /tmp/uat-sample.journal`
4. The fixture now includes (appended at the end, so every line number the
   *1.0.2* checklist references is unaffected): declared `account`/`payee`
   directives (`expenses:rent`, `income:salary`, `Landlord`), a few more
   distinct accounts (`expenses:food:organic`, `income:salary`,
   `expenses:rent`) for prefix/regex testing, and two transactions dated
   in the second half of last month (`2026-08-15`, `2026-08-20` — adjust
   if you're running this well after 2026-09) so a relative-date filter
   has something recent to actually match.

## 1 — Transaction Filter (`Ctrl+O`) — smart dates

- [ ] Press **Ctrl+O**. The filter popup appears with Date from / Date to
      / Account / Payee fields and **Apply**/**Clear** buttons.
- [ ] Leave every field blank, click **Apply** (or press Enter in a
      field).
  - **Expected:** every transaction still visible — an all-blank filter
    matches everything, it isn't rejected as invalid.
- [ ] Set **Date from** to `last month` (or `-30d`), leave Date to blank,
      **Apply**.
  - **Expected:** `Landlord` and `Employer` (dated in the second half of
    last month) are visible; the `2024-*` transactions and the January/
    February 2024 filler transactions are hidden.
- [ ] Clear and retry with **Date from** = `2024-02-05`, **Date to** =
      `2024-02-10`.
  - **Expected:** only `Filler transaction 5` through `Filler transaction
    10` are visible (inclusive both ends).
- [ ] Try an invalid date string, e.g. `not a date`, **Apply**.
  - **Expected:** a warning notification, previous view unchanged (not
    silently treated as "no filter").

## 2 — Transaction Filter — account / payee, substring and regex

- [ ] **Clear** the filter first. Set **Account** to `food` (plain
      substring), **Apply**.
  - **Expected:** both `Groceries` transactions and `Organic Grocer`
    (posts to `expenses:food:organic`) are visible; everything else
    hidden.
- [ ] **Clear**. Set **Account** to `^expenses:food$` (regex — exact
      match, no sub-account), **Apply**.
  - **Expected:** only the `expenses:food` postings match — `Organic
    Grocer` (`expenses:food:organic`) is now excluded, unlike the plain
    substring case above.
- [ ] **Clear**. Set **Payee** to `^Landlord$`, **Apply**.
  - **Expected:** only the `Landlord` transaction visible.
- [ ] **Clear**. Set **Account** to an invalid regex, e.g. `expenses:(`,
      **Apply**.
  - **Expected:** a warning notification naming the bad regex; filter not
    applied.

## 3 — Transaction Filter — editing while filtered, and Clear

- [ ] With a filter active showing a subset (e.g. the `food` substring
      filter from §2), edit one of the visible transactions' amount.
- [ ] Click **Clear**.
  - **Expected:** the full journal is restored, and your edit is present
    on the correct transaction (edits merge back, they aren't lost).
- [ ] Re-apply any filter, then press **Ctrl+S**.
  - **Expected:** save succeeds, the view returns to **All transactions**,
    and the saved file on disk contains every transaction (not just the
    filtered subset) — check the status bar at the top reads "View: All
    transactions" afterward.

## 4 — Filter / Ctrl+L mutual exclusivity

- [ ] Press **Ctrl+L** once (view becomes "Cleared only").
- [ ] Press **Ctrl+O**, apply any criteria filter (e.g. Account =
      `rent`).
  - **Expected:** the view switches to the criteria filter's results
    (not a combination of "cleared AND rent") — the status bar reads
    "View: Filtered (Ctrl+O)".
- [ ] Press **Ctrl+L**.
  - **Expected:** the criteria filter exits, and Ctrl+L starts a fresh
    cycle (**Cleared only**) — not "Unreconciled" continuing from
    wherever the old cycle left off.

## 5 — Tab autocomplete — accounts

- [ ] Go to the end of the file, start a new transaction with a posting
      line, and type `    expenses:f` (4-space indent).
- [ ] Press **Tab**.
  - **Expected:** completes to `expenses:food` immediately (the shortest
    match), and a suggestion bar appears at the bottom of the editor
    showing all matches (`expenses:food`, `expenses:food:organic`).
- [ ] Press **Tab** again.
  - **Expected:** cycles to `expenses:food:organic` (or the next
    candidate) — the line's text updates in place.
- [ ] Type a character that doesn't match anything (e.g. `zzz`), press
      **Tab**.
  - **Expected:** nothing happens (falls through) — no crash, no stale
    suggestion inserted.
- [ ] Try `    income:` then **Tab**.
  - **Expected:** completes to `income:salary` — confirms a *declared but
    otherwise only-once-used* account still completes correctly.

## 6 — Tab autocomplete — payees

- [ ] On a new transaction header line, type `2026-09-09 Land` then
      **Tab**.
  - **Expected:** completes to `2026-09-09 Landlord` — confirms the
    *declared* `payee Landlord` directive is picked up even though the
    word "Landlord" only appears once in an actual transaction.
- [ ] Position the cursor **inside the date** (not yet past the flag/
      code/payee boundary) and press Tab.
  - **Expected:** normal Tab fallthrough (focus-cycle) — no completion
    attempted on the date itself.

## 7 — Tab autocomplete — Escape, and index refresh on save

- [ ] With a suggestion bar showing (from §5 or §6), press **Escape**.
  - **Expected:** the bar disappears; the already-inserted text is left
    as-is (Escape dismisses the *suggestions*, it doesn't undo the
    insertion — use Ctrl+Z for that if wanted).
- [ ] Type a brand-new account nobody's used yet, e.g.
      `    expenses:brand_new_thing    5.00 EUR`, on its own transaction.
- [ ] Immediately try to Tab-complete `expenses:brand_new` on a *different*
      new line.
  - **Expected:** no match yet — the index hasn't been rebuilt since your
    last save.
- [ ] Press **Ctrl+S** to save, then retry the same Tab-completion.
  - **Expected:** now completes — confirms the index refreshes after
    save, as designed (not per-keystroke).
