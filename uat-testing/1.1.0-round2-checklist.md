# UAT Checklist — 1.1.0 Round 2 (fixes from round-1 feedback)

**Branch:** `release/1.1.0`
**Covers:** every fix made in response to the round-1 UAT report — see
`CHANGELOG.md [Unreleased]` for the full write-up of each. This checklist
re-verifies the specific things that were reported broken, plus the
combine-filter behavior, which is genuinely new and hasn't been UAT'd yet.
**Not re-covered here** (already signed off in round 1, unaffected by
these fixes): basic account/payee substring+regex filtering, edit-while-
filtered-then-save, Tab-completing accounts/payees, Escape dismissing the
suggestion bar, index-refresh-on-save. See
[`1.1.0-filter-autocomplete-checklist.md`](1.1.0-filter-autocomplete-checklist.md)
for those if you want to re-run them too.
**Prerequisite:** [`SETUP.md`](SETUP.md) — make sure you're on the latest
`release/1.1.0` (`git pull`), not just wherever round 1 left off.

## Setup

1. `git pull` on `release/1.1.0`, reinstall if `pyproject.toml` changed
   (`pip install -e ".[dev]"`), confirm `pytest --tb=short` is green.
2. Copy the fixture to scratch — it's been updated since round 1 (two
   transactions are now marked cleared, `*`, so there's something for
   `Ctrl+L`'s "Cleared only" to combine with):
   ```
   cp uat-testing/uat-sample.journal /tmp/uat-sample.journal
   ```
   PowerShell: `Copy-Item uat-testing\uat-sample.journal $env:TEMP\uat-sample.journal`
3. Launch: `python -m ledgerkit_editor /tmp/uat-sample.journal`
4. What's cleared in this fixture (relevant for §5 below): `2024-02-10
   Filler transaction 10` (posts to `expenses:misc`) and `2026-08-15
   Landlord` (posts to `expenses:rent`). Nothing else is cleared.

## 1 — Empty Ctrl+O filter is a true no-op

- [ ] Note the file-path bar at the top — should show no "· modified"
      indicator on a freshly-opened file.
- [ ] Press **Ctrl+O**, leave every field blank, click **Apply**.
  - **Expected:** every transaction still visible, and — this is the
    actual bug that was fixed — the file-path bar still shows **no**
    "modified" indicator, and amounts don't visibly re-align/reformat.
- [ ] Press **Ctrl+S** anyway, then check the file on disk (or just note
      whether it prompted/behaved like there was nothing to save).

## 2 — Clear button empties its own fields

- [ ] Press **Ctrl+O**, type something into Account and Payee (e.g.
      `food` and `Groceries`), click **Apply** to confirm it filters.
- [ ] Click **Clear**.
  - **Expected:** full journal restored, **and** the Account/Payee/Date
    fields in the popup are now empty (not just the filter cleared) —
    check by looking at the input boxes themselves.

## 3 — Ctrl+O visible in the footer

- [ ] Look at the bottom toolbar/footer without pressing anything.
  - **Expected:** a `^O Filter transactions` entry is visible without
    needing to scroll. (`Ctrl+S` no longer shows there — that's
    intentional, freeing up the space.)

## 4 — Autocomplete suggestion bar actually renders

- [ ] Go to the end of the file, add a posting line, type
      `    expenses:` and press **Tab**.
  - **Expected:** completes to the shortest match, **and** a visible
    suggestion bar with candidate text appears just above the footer —
    not blank/invisible.

## 5 — "last month" is bounded to that calendar month

- [ ] Press **Ctrl+O**, set **Date from** to `last month`, leave **Date
      to** blank, **Apply**.
  - **Expected:** shows only transactions dated in the *previous*
    calendar month relative to today — with this fixture, that's
    whichever of `Landlord` (Aug 15) / `Employer` (Aug 20) falls in last
    month given today's actual date (adjust expectations if you're
    running this well after 2026-09; the fixture's dates are fixed).
    Critically: nothing from *this* month should appear, and nothing
    from 2024 should appear either.

## 6 — Ctrl+O and Ctrl+L now COMBINE (AND) — new behavior, please test thoroughly

This is the one that changed the most since round 1. Previously, applying
one filter discarded the other; now they narrow together.

- [ ] Press **Ctrl+L** once → "Cleared only".
  - **Expected:** exactly 2 transactions visible: `Filler transaction 10`
    and `Landlord` (the only two marked `*` in this fixture).
- [ ] With that still active, press **Ctrl+O**, set **Account** to
      `rent`, **Apply**.
  - **Expected:** narrows further to just `Landlord` (posts to
    `expenses:rent` — `Filler transaction 10` posts to `expenses:misc`,
    so it drops out). The status bar at the top should now read
    something like **"View: Cleared only + Filtered (Ctrl+O)"** —
    describing both, not just one.
- [ ] Click **Clear** on the filter popup.
  - **Expected:** the Ctrl+O criteria filter goes away, but **Cleared
    only stays active** — you should be back to seeing both
    `Filler transaction 10` and `Landlord`, *not* the full journal.
- [ ] Press **Ctrl+L** twice more (cycling Cleared → Unreconciled → All).
  - **Expected:** normal 3-state cycling, same as before — this part
    shouldn't feel any different when Ctrl+O isn't involved.
- [ ] Now, from **All**, press **Ctrl+O** first this time — set
      **Account** to `expenses:misc`, **Apply**.
  - **Expected:** shows all 20 `Filler transaction` entries (all post to
    `expenses:misc`), regardless of cleared status.
- [ ] With that still active, press **Ctrl+L** once → "Cleared only".
  - **Expected:** narrows to just `Filler transaction 10` (the only
    *cleared* one posting to `expenses:misc`). Status bar should again
    describe both.
- [ ] Press **Ctrl+L** two more times to cycle back to **All**.
  - **Expected:** the Ctrl+O `expenses:misc` filter should **still be
    active** — you should see all 20 Filler transactions again, not the
    full journal. (This is the "cycling Ctrl+L back to All doesn't
    discard Ctrl+O" case.)
- [ ] Finally, click **Ctrl+O → Clear** to get back to a clean slate.
  - **Expected:** full journal restored, status bar reads "View: All
    transactions".
