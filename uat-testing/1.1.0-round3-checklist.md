# UAT Checklist — 1.1.0 Round 3 (filter count + filter-popup autocomplete)

**Branch:** `release/1.1.0`
**Covers:** the two features added after round 2 — see `CHANGELOG.md
[Unreleased]` for the full write-up of each:

1. The view-filter status bar now shows a **visible/total transaction
   count** whenever a filter is active.
2. **Tab autocomplete now also works in the Ctrl+O filter popup's**
   Account and Payee fields.

**Not re-covered here** (already signed off in rounds 1–2, unaffected by
these two additions): basic filtering itself, empty-filter no-op, Clear
button field-reset, footer visibility, main-editor autocomplete, "last
month" bounding, and the Ctrl+O/Ctrl+L combine behavior's visibility
results. See
[`1.1.0-round2-checklist.md`](1.1.0-round2-checklist.md) if you want to
re-run those.
**Prerequisite:** [`SETUP.md`](SETUP.md) — `git pull` first, this fixture
has been extended again since round 2.

## Setup

1. `git pull` on `release/1.1.0`, `pip install -e ".[dev]"` if
   `pyproject.toml` changed, confirm `pytest --tb=short` is green.
2. Copy the fixture to scratch:
   ```
   cp uat-testing/uat-sample.journal /tmp/uat-sample.journal
   ```
   PowerShell: `Copy-Item uat-testing\uat-sample.journal $env:TEMP\uat-sample.journal`
3. Launch: `python -m ledgerkit_editor /tmp/uat-sample.journal`
4. This fixture has **26 transactions total**, of which **2 are cleared**
   (`Filler transaction 10` and `Landlord`) — same as round 2, unchanged
   since then. Known accounts include `expenses:food`, `expenses:misc`,
   `expenses:rent`, `expenses:food:organic`, `assets:bank:checking`,
   `equity:opening-balances`, `income:salary`; known payees include
   `Landlord` (declared but check the numbers work out — it's also used).

## 1 — Transaction count on the status bar

- [ ] With no filter active, look at the status bar (top of the editor).
  - **Expected:** reads "View: All transactions" — **no** count shown
    (nothing's being filtered, so a count would be redundant).
- [ ] Press **Ctrl+L** once → "Cleared only".
  - **Expected:** status bar reads **"View: Cleared only (2/26)"**.
- [ ] Press **Ctrl+O**, set **Account** to `misc`, **Apply** (combines
      with the still-active Cleared filter).
  - **Expected:** narrows to just `Filler transaction 10` (the only
    cleared transaction posting to `expenses:misc`), status bar reads
    **"View: Cleared only + Filtered (Ctrl+O) (1/26)"**.
- [ ] Click **Clear** to drop the Ctrl+O side, then **Ctrl+L** twice more
      to cycle back to **All**.
  - **Expected:** count disappears again once back at "All transactions".
- [ ] Press **Ctrl+O**, set **Date from** = `2024-02-05`, **Date to** =
      `2024-02-10`, **Apply** (no Ctrl+L this time).
  - **Expected:** 6 transactions visible (`Filler transaction 5` through
    `10`), status bar reads **"View: Filtered (Ctrl+O) (6/26)"**.
- [ ] With that filter still active, go to the end of the visible
      (filtered) text and add a brand-new transaction dated inside that
      range, e.g.:
      ```
      2024-02-07 New Test Txn
          expenses:misc    1.00 EUR
          assets:bank:checking
      ```
  - **Expected:** the count doesn't update per-keystroke (that's by
    design — see the parenthetical below). Press **Ctrl+S**.
  - **Expected:** the file saves, the view returns to **All transactions**
    (Ctrl+S always exits any active filter), and re-opening the file (or
    checking the file on disk directly) shows **27 transactions total**,
    including `New Test Txn`.
      (Correction from an earlier draft of this checklist: pressing
      `Ctrl+L` a couple of times as an alternative "trigger a recompute"
      step does **not** just refresh the same date-range count — each
      press also changes which cleared-state is required, so the
      *visible* count you'd see along the way reflects a different,
      narrower combined filter each time, not simply "+1". The
      transaction itself is never lost either way — only the visible
      count's exact number depends on which combined state you're
      looking at when you check it. If you want to verify persistence
      without that complication, `Ctrl+S` directly is the simpler check.)
- [ ] Click **Clear** to reset before moving on.

## 2 — Tab autocomplete in the filter popup

- [ ] Press **Ctrl+O**. Click into (or Tab to) the **Account** field, type
      `expenses:` (no more), then press **Tab**.
  - **Expected:** the field completes to one of the known `expenses:*`
    accounts immediately (don't worry about which one specifically).
- [ ] Press **Tab** again (and again a few more times).
  - **Expected:** each press cycles the field's value to a *different*
    `expenses:*` account (`expenses:food`, `expenses:misc`,
    `expenses:rent`, `expenses:food:organic`) — eventually wrapping back
    to the first one. No suggestion list/popup is expected to appear here
    (unlike the main editor) — just the field's text changing.
- [ ] Clear the Account field. Click into the **Payee** field, type
      `Land`, press **Tab**.
  - **Expected:** completes to `Landlord`.
- [ ] Clear the Payee field. Click into **Date from**, type `2024`, press
      **Tab**.
  - **Expected:** the field's text is **unchanged** (`2024`) — Tab only
    autocompletes Account/Payee, not the date fields. Focus should move
    on as ordinary Tab would.
- [ ] Type something with no match anywhere, e.g. `zzz_nonexistent`, into
      **Account**, press **Tab**.
  - **Expected:** field text unchanged, no error/crash, focus moves on.
- [ ] After completing a value with Tab, press **Apply** to confirm the
      completed value actually works as a real filter (not just cosmetic
      text in the box).
